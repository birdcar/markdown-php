Context · 01

The problem

01markdown-php is a Composer monorepo with three packages — birdcar/markdown-php at the repo root, birdcar/markdown-laravel, and birdcar/markdown-filament — but Packagist serves exactly one package per Git repository. Submitting the monorepo as-is publishes only the core package; the Laravel and Filament packages stay uninstallable. The `composer require birdcar/markdown-laravel` and `birdcar/markdown-filament` lines already advertised in the READMEs do not work for anyone.

02There is no release automation, no tags, and no CI. The sub-packages wire themselves together with `@dev` path-repo constraints and `minimum-stability: dev`, which cannot produce stable published releases. The root package is also a dirty publish target: its dist archive would bundle `packages/`, `docs/`, `tests/`, and an unresolvable `spec/` git submodule, none of which a consumer of the core library needs.

Commit · 02

Goals

1 All three packages are installable from Packagist by external users via `composer require birdcar/markdown-{php,laravel,filament}`.
2 Releases are fully automated from Conventional Commits: merging a Release PR cuts a tag, splits the sub-packages, and publishes to Packagist with no manual tagging.
3 One lockstep version across all three packages, starting at v0.1.0, with inter-package dependencies expressed via Composer's `self.version`.
4 CI verifies every PHP and Laravel version the composer.json files claim — constrained to currently non-EOL releases only.
5 The published core package archive is clean: no monorepo scaffolding, no submodule.
Signal · 03

Done when…

7 signals
  • 01 Merging the Release PR creates tag v0.1.0 and a GitHub Release on the monorepo.
  • 02 The split job mirrors packages/laravel → birdcar/markdown-laravel and packages/filament → birdcar/markdown-filament and pushes the v0.1.0 tag to both split repos.
  • 03 Packagist shows version 0.1.0 for all three packages after the auto-update webhook fires.
  • 04 In a clean scratch project with no path repositories, `composer require birdcar/markdown-filament` resolves the full chain (filament → laravel → php) entirely from Packagist.
  • 05 The CI matrix passes: PHP 8.2 / 8.3 / 8.4 / 8.5 × Laravel 12 / 13, run with both --prefer-lowest and --prefer-stable, plus Filament v4.
  • 06 `composer validate --strict` passes for all three composer.json files.
  • 07 A downloaded dist archive of birdcar/markdown-php contains src/ but not packages/, docs/, tests/, or spec/.

MVP — must ship ×6
  • composer.json release-readiness across all 3 packages: @dev → self.version, drop/relax minimum-stability: dev + prefer-stable— Without this the packages cannot resolve as stable published releases.
  • Narrow dependency constraints to non-EOL versions: illuminate/support → ^12.0|^13.0, orchestra/testbench aligned (^10.0|^11.0); keep php ^8.2 (covers 8.2–8.5)— Laravel 10 and 11 are EOL as of 2026-05-29; the plan should only claim support it tests.
  • .gitattributes with export-ignore for packages/, docs/, tests/, spec/, .github/, phpunit.xml on the root package— Keeps the published core dist archive clean and free of the unresolvable spec/ submodule.
  • release-please config + manifest: simple release-type, single root '.' component, lockstep, bump-minor-pre-major=true, bump-patch-for-minor-pre-major=false, tag format v${version}— Automates versioning/changelog/tagging from Conventional Commits without touching composer.json version fields.
  • release.yml: release-please job → split job gated on release_created, re-runs tests, then splitsh-lite via danharrin/monorepo-split-github-action propagating the tag— This is the publish pipeline.
  • Reusable tests.yml (workflow_call) matrix + ci.yml invoking it on PR and push to main— Gates the Release PR and is reused by the split job's re-gate.
Full — target outcome ×4
  • RELEASING.md runbook: one-time provisioning (create split repos, PAT secret, Packagist submission + webhook, branch protection) and the ongoing merge-the-Release-PR flow— The manual steps are the easiest part to get wrong.
  • MIT LICENSE file at root + packages/laravel + packages/filament— Packagist flags missing LICENSE files; split repos inherit their subtree's copy.
  • composer extra.branch-alias (dev-main => 0.x-dev) on all 3 packages— Lets consumers install dev-main and keeps self.version resolvable on the default branch.
  • --prefer-lowest and --prefer-stable legs in the matrix— Verifies both the floor and ceiling of each declared version range.
Stretch — if time permits ×2
  • PHPStan (level 8) added as a CI job alongside tests
  • Scheduled weekly CI run to catch dependency drift
Out of scope — said no on purpose
  • Creating the birdcar/markdown-laravel and birdcar/markdown-filament GitHub repos — Requires your GitHub account; documented in RELEASING.md and executed in the human-gate phase.
  • Generating the split PAT secret — Requires your account and repo admin rights.
  • Submitting packages to Packagist and enabling the auto-update webhook/GitHub App — Requires your Packagist account.
  • Configuring branch protection requiring the tests check — Repo admin action; documented in the runbook.
  • Independent per-package versioning — Explicitly rejected in favor of lockstep + self.version.
Future — someday, maybe
  • Promote to v1.0.0 once the BFM API stabilizes.
  • Add/remove PHP and Laravel matrix legs as versions release or reach EOL.
